Este guia aborda como remover OmniRoute do seu sistema de forma limpa.

## Reverter configuração do cliente

O desinstalador interrompe o processo OmniRoute gerido pelo PM2, se presente, e deixa a configuração do cliente em vigor. Os clientes que ainda apontam para OmniRoute perdem a ligação quando esta é interrompida. A remoção completa também elimina o diretório de dados, `~/.omniroute` por defeito, juntamente com os seus backups de configuração do cliente.

### 1. Utilize o painel enquanto OmniRoute está a ser executado

Aberto** Código CLI** (`/dashboard/cli-code`) no painel e encontre o** Código Claude** cartão.** Candidatar-se** escreve no ficheiro de definições do código Claude do host OmniRoute, `~/.claude/settings.json` por defeito. Se tiver um backup antes de aplicar as definições OmniRoute, abra** Cópias de segurança** e restaurá-lo. Caso contrário, selecione** Reiniciar** para remover as definições do gateway do `env`. Aplicar e repor primeiro faça uma cópia de segurança do ficheiro existente. Os backups são armazenados em `<DATA_DIR>/backups`.

Se `CLI_ALLOW_CONFIG_WRITES=false` ou o painel não estiverem disponíveis, reverta o ficheiro manualmente. Se OmniRoute for executado no Docker e o cliente for executado no host, reverta a configuração do host. Os ficheiros num contentor desmontado não têm efeito no cliente host.

### 2.º Reverta as restantes alterações manualmente

Para o código Claude, verifique `~/.claude/settings.json`, o `settings.json` em `CLAUDE_CONFIG_DIR` se definido e o `.claude/settings.json` do projeto. O reset remove as seguintes chaves de `env`. Remova os valores adicionados para OmniRoute ou restaure os valores anteriores.

- `"ANTHROPIC_BASE_URL"`, `"ANTHROPIC_AUTH_TOKEN"` e `"ANTHROPIC_API_KEY"`
- `"ANTHROPIC_DEFAULT_OPUS_MODEL"`, `"ANTHROPIC_DEFAULT_SONNET_MODEL"` e `"ANTHROPIC_DEFAULT_HAIKU_MODEL"`
- `"API_TIMEOUT_MS"`

A reposição deixa `ANTHROPIC_MODEL` em `env` e as definições `model` e `apiKeyHelper` de nível superior em vigor. Remova-os ou restaure-os manualmente se selecionarem um modelo ou credencial OmniRoute. Deixe de utilizar qualquer perfil OmniRoute criado por `omniroute setup-claude` em `~/.claude/profiles/<name>/` ou reverta o seu `settings.json`. O comando setup grava o perfil sem alterar o ficheiro de definições padrão ou guardar um token. Remova ou restaure as exportações correspondentes nos ficheiros de arranque do shell e limpe os valores antigos do shell atual. `omniroute launch` e `omniroute run claude` configuram o gateway URL e o token apenas para o processo filho.

Para Codex, restaure o fornecedor e o modelo anteriores em `~/.codex/config.toml` se este contiver `model_provider = "omniroute"`. Remova `[model_providers.omniroute]` se tiver sido adicionado a este gateway. Restaure ou remova `openai_base_url` se apontar para OmniRoute. Para clientes compatíveis com OpenAI, restaure ou limpe `OPENAI_BASE_URL` onde quer que o configure para OmniRoute.

### 3.º Verifique se o cliente funciona com OmniRoute parado

Verifique as definições padrão do código Claude e o ambiente shell atual.

```bash
grep -n ANTHROPIC ~/.claude/settings.json
env | grep ANTHROPIC
```

Nenhuma das verificações deve mostrar `ANTHROPIC_BASE_URL` a apontar para OmniRoute. Se utilizar um perfil ou definições de projeto, verifique também esses ficheiros. Com OmniRoute interrompido e a sua autenticação normal restaurada, execute Claude Code diretamente.

```bash
claude -p "say hello"
```

O código Claude deve responder utilizando a configuração restaurada. Se ainda apontar para o gateway interrompido, o pedido falhará com um erro de ligação.

## Desinstalação rápida (v3.6.2 +)

> [Reverter primeiro a configuração do cliente](#revert-client-configuration), enquanto OmniRoute ainda está a ser executado.

OmniRoute fornece dois scripts integrados para uma remoção limpa:

### Mantenha os seus dados

```bash
npm run uninstall
```

Isto remove a aplicação OmniRoute mas** conservas** a sua base de dados, configurações, chaves API e configurações do fornecedor em `~/.omniroute/`. Utilize isto se planeia reinstalar mais tarde e deseja manter a sua configuração.

### Remoção completa

```bash
npm run uninstall:full
```

Isto remove o aplicativo** e apaga permanentemente** todos os dados:

- Base de dados (`storage.sqlite`)
- Configurações do fornecedor e chaves API
- Arquivos de backup
- Arquivos de registo
- Todos os ficheiros no diretório `~/.omniroute/`

> ⚠️** Aviso:** `npm run uninstall:full` é irreversível. Todas as ligações do seu fornecedor, combos, chaves API e histórico de utilização serão eliminados permanentemente.

## Desinstalação manual

> [Reverter primeiro a configuração do cliente](#revert-client-configuration), enquanto OmniRoute ainda está a ser executado.

### Instalação global NPM

```bash
# Remove the global package
npm uninstall -g omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

### Instalação global pnpm

```bash
pnpm uninstall -g omniroute
rm -rf ~/.omniroute
```

### Docker

```bash
# Stop and remove the container
docker stop omniroute
docker rm omniroute

# Remove the volume (deletes all data)
docker volume rm omniroute-data

# (Optional) Remove the image
docker rmi cheaperinference/omniroute:latest
# Older installs pulled the legacy name:
docker rmi diegosouzapw/omniroute:latest
```

### Docker Compor

```bash
# Stop and remove containers
docker compose down

# Also remove volumes (deletes all data)
docker compose down -v
```

### Aplicação de desktop Electron

**Windows:**

- Abrir `Settings → Apps → OmniRoute → Uninstall`
- Ou execute o desinstalador NSIS no diretório de instalação

**macOS:**

- Arraste `OmniRoute.app` do `/Applications` para a Reciclagem
- Remover dados: `rm -rf ~/Library/Application Support/omniroute`

**Linux:**

- Remova o ficheiro AppImage
- Remover dados: `rm -rf ~/.omniroute`

### Instalação de origem (git clone)

```bash
# Remove the cloned directory
rm -rf /path/to/omniroute

# (Optional) Remove data directory
rm -rf ~/.omniroute
```

## Diretórios de Dados

Por predefinição, o OmniRoute armazena os dados nas seguintes localizações:

| Plataforma         | Caminho Predefinido           | Substituição                           |
| ------------------ | ----------------------------- | -------------------------------------- |
| Linux              | `~/.omniroute/`               | variável de ambiente `DATA_DIR`        |
| macOS              | `~/.omniroute/`               | variável de ambiente `DATA_DIR`        |
| Windows            | `%APPDATA%/omniroute/`        | variável de ambiente `DATA_DIR`        |
| Docker             | `/app/data/` (volume montado) | variável de ambiente `DATA_DIR`        |
| Compatível com XDG | `$XDG_CONFIG_HOME/omniroute/` | variável de ambiente `XDG_CONFIG_HOME` |

### Ficheiros no diretório de dados

| Ficheiro/Diretório   | Descrição                                                               |
| -------------------- | ----------------------------------------------------------------------- |
| `storage.sqlite`     | Base de dados principal (fornecedores, combinações, definições, chaves) |
| `storage.sqlite-wal` | Registo de escrita antecipada do SQLite (temporário)                    |
| `storage.sqlite-shm` | Memória partilhada do SQLite (temporária)                               |
| `call_logs/`         | Arquivos dos conteúdos dos pedidos                                      |
| `backups/`           | Cópias de segurança automáticas da base de dados                        |
| `log.txt`            | Registo legado de pedidos (opcional)                                    |

## Verificar a Remoção Completa

Após a desinstalação, verifique se não existem ficheiros restantes:

```bash
# Verificar o pacote npm global
npm list -g omniroute 2>/dev/null

# Verificar o diretório de dados
ls -la ~/.omniroute/ 2>/dev/null

# Verificar processos em execução
pgrep -f omniroute
```

Se algum processo ainda estiver em execução, pare-o:

```bash
pkill -f omniroute
```
